Why BUZA

Finding support should not create another admin problem.

The prototype is built around a practical idea: tutoring is easier when discovery, availability, bookings and the lesson timetable are part of the same journey.

Rather than treating a tutor listing as the end product, BUZA is exploring how the pieces around a lesson can fit together for both the learner and the tutor.

01Find clearly

Search around the learner's actual subject, grade and support need.

02Schedule realistically

Availability and existing commitments matter before a booking is made.

03Follow through

A lesson is a journey from request to confirmation, timetable, session and feedback.

What the current prototype explores

Built around both sides of the lesson

Learner journey. Tutor workflow.

The current prototype does not treat tutors as static listings. Both roles have actions, schedules and responsibilities.

L
LEARNER SIDE

Find support and keep track of it.

  • Discover tutors by learning need
  • Compare tutoring and session options
  • Request one-to-one bookings
  • Join available group sessions
  • See booked learning in a personal timetable
  • Receive updates and submit lesson feedback
T
TUTOR SIDE

Manage teaching as a real schedule.

  • Set available teaching windows
  • Block unavailable time
  • Create advertised group classes
  • Accept or decline booking requests
  • See teaching commitments in a timetable
  • Move a demo lesson through start, end and feedback
The product journey being designed

From “I need help” to “lesson completed.”

  1. 01Find

    Start with the learner's subject, grade or academic need.

  2. 02Choose

    Understand the tutor and the kind of session being offered.

  3. 03Book

    Select a time that works without creating a timetable clash.

  4. 04Learn

    Use the booked session as the centre of the learning interaction.

  5. 05Close out

    Record feedback and complete the lesson cycle cleanly.

Development boundary

A working prototype is not yet a public tutoring service.

BUZA still needs production infrastructure, operational rules and safeguarding before learners, families or tutors should rely on it as a live marketplace.

The current demo stores its working state locally in the browser and uses mock users, tutors, bookings and lesson data. The public Veni Publishing site will not present those demo profiles, ratings or prices as real.

NOT PUBLIC YET

Before BUZA can launch, the real service still needs:

  • 01
    Production accounts + authenticationReal learner, parent and tutor identity flows.
  • 02
    Tutor verificationCredential, identity and suitability processes that are more than a demo badge.
  • 03
    Persistent backend infrastructureA real database and cross-device state rather than browser-local demo storage.
  • 04
    Payments, payouts + disputesProduction financial workflows and clear rules for cancellations, refunds and resolution.
  • 05
    Real lesson technologyVideo/audio, chat, screen sharing and resource tools still require live integration.
  • 06
    Safeguarding + privacyChild-safe operational, data and communication policies must be locked before public use.
